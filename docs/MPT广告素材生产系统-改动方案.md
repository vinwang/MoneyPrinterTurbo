# MoneyPrinterTurbo 广告素材生产系统 · 改动方案（v7）

> v7 新增第十一节“本地素材语义匹配与成片时间轴”。本轮已开始实施并接入本地生成闭环；仍未完成的模型能力、真实素材和性能验收不能以既有测试结果代替。v6 的外挂后处理能力与历史验证记录保留。
>
> 核心原则：复用现有 MPT 生成与外挂后处理能力。原外挂方案只调用 CLI；v7 本地素材功能允许在本仓库 WebUI、素材选择和合成入口做必要接入，不改变人声选择、非本地素材来源和原有后处理行为。阶段之间通过明确清单连接，所有失败显式暴露，不能静默降级。

## 一、结论与范围

| 项目 | 决定 |
|---|---|
| 总体架构 | 保留“素材选择 → MPT 生成 → 外挂后处理”三阶段 |
| MPT 改动 | 原外挂保留 CLI 入口；本地语义匹配按第十一节接入 WebUI 与合成时间轴 |
| 旁白字幕 | 继续由 MPT 原生字幕系统渲染 |
| 指定文字 | 由 `post_process.py` 独立叠加，支持无动画、弹簧缩放、闪烁变大、逐字变大 |
| 水印 | 由 `post_process.py` 叠加，位置由任务配置决定 |
| 配置格式 | JSON；严格校验版本、字段、枚举、时间、路径和坐标 |
| 任务标识 | 外挂 `job_id` 与 MPT 运行时生成的 `mpt_task_id` 分开记录 |
| 默认行为 | `watermark.position=top_right`，`custom_texts=[]`；指定文字不是必选层 |
| 发布规格 | 以广告版位的确认规格为准；文档中的 1080×1920 只作为竖屏测试预设 |

### 不在本次范围内

- 不把指定文字字段加入 `VideoParams` 或 MPT batch JSON。
- 不修改 MPT 字幕排版、TTS 和在线素材下载行为；本地素材合成时间轴按第十一节改进，不把新规则带入非本地来源。
- 不在 selector 中自动发布未经人工确认的价格、折扣、功效或合规声明。
- 多行排版和并发规模属于待确认的实现范围；复杂单行字素已实现，不能将“多行待确认”误写成“复杂字素不支持”。

## 二、总体架构

```text
素材库（视频/音乐，已按分类整理）
        │
        ▼
┌────────────────────────────────────────┐
│ 阶段一｜selector.py                    │
│ 主题/活动信息 → 素材与 BGM 选择         │
│ → 生成 MPT batch JSONL                  │
│ → 生成后处理配置                        │
│ → 保存 job_id、输入快照和配置校验结果    │
└────────────────────────────────────────┘
        │
        ▼
┌────────────────────────────────────────┐
│ 阶段二｜官方 MPT CLI                    │
│ --batch-file 运行                       │
│ → stdout/结果文件记录 mpt_task_id       │
│ → 收集 result.videos 的全部输出          │
└────────────────────────────────────────┘
        │
        ▼
┌────────────────────────────────────────┐
│ 阶段三｜post_process.py                 │
│ 读取任务映射和配置                       │
│ → 叠加 Logo 水印                         │
│ → 叠加指定文字及动画                     │
│ → 按目标规格一次性导出                   │
│ → ffprobe 校验并登记最终产物             │
└────────────────────────────────────────┘
        │
        ▼
      output/final/{job_id}/{task_index}/{render_key}/{variant}.mp4
```

### 2.1 标识与目录契约

阶段一不能预先假设 MPT 的 task ID。当前 CLI 在执行 batch 时生成 UUID，并返回 `index`、`task_id`、`status` 和 `result`；因此外挂必须使用自己的 `job_id` 管理一次完整流程，并在阶段二完成后写入映射：

```text
job_id + task_index ──(阶段二)──> mpt_task_id + result.videos[]
```

建议目录：

```text
project/
├── mpt/                             # 官方 MoneyPrinterTurbo，不修改
├── assets/                          # 素材库
├── manifest/                        # 分类清单
├── state/                           # 素材预占/提交状态
├── watermark/
│   └── logo.png
├── scripts/
│   ├── build_manifest.py
│   ├── selector.py
│   ├── post_process.py
│   └── run_pipeline.sh
└── output/
    ├── jobs/{job_id}/
    │   ├── input.json
    │   ├── batch.jsonl
    │   ├── post_process_specs/{task_index}.json
    │   ├── mpt_result.json
    │   └── status.json
    ├── mpt_raw/{job_id}/{task_index}/{variant}.mp4
    └── final/{job_id}/{task_index}/{render_key}/{variant}.mp4
```

`status.json` 至少记录：`job_id`、`task_index`、`mpt_task_id`、阶段状态、输入脚本哈希、配置哈希、原始输出路径、最终输出路径、错误阶段和错误信息。最终输出不得覆盖原始 MPT 输出。

一个 `job_id` 对应一次 batch；`task_index` 从 1 开始，与冻结后的 batch 条目顺序一一对应，运行后不能重排。`variant` 从 1 开始，按该条目 `result.videos` 列表顺序编号。同一 task 的变体共用该 task 配置并分别按实际时长校验；不同文案、水印或版位使用不同 task 配置。`status.json` 使用 `tasks[]`，每条含 `variants[]`，分别保存状态，不能用单个成功/失败字段覆盖整批明细。

`render_key` 是第六节定义的渲染输入指纹。该目录布局为外挂目录，不要求搬动当前仓库；MPT 根目录由运行入口显式指定。

### 2.2 字幕分层与参数映射

| 图层 | 时序与参数 | 配置归属 |
|---|---|---|
| 旁白字幕 | 跟随配音打轴；`subtitle_enabled`、`font_name`、`font_size`、`text_fore_color`、`stroke_color`、`stroke_width` | MPT batch 的 `VideoParams` |
| 旁白位置与动画 | `subtitle_position`、`custom_position`、`subtitle_display_mode`、`subtitle_animation`；枚举以当前模型为准 | MPT batch 的 `VideoParams` |
| 指定文字 | 独立起止时间、字体、颜色、描边、中心位置及四种动画 | 外挂每任务后处理配置 |

两层时间和样式独立，但仍可能视觉遮挡。验收需检查 Logo、指定文字和旁白的重叠；不能把“配置独立”解释为自动避让。外挂的 `font_size_px` 与 MPT 的 `font_size` 不混用字段名。

## 三、阶段一：素材选择与任务生成

### 3.1 输入和选择规则

- 主题、活动信息、目标版位、语言、品牌色和确认后的促销事实是结构化输入。
- LLM 只能从 manifest 的分类、素材 ID 和 BGM ID 中选择；选择结果必须经过本地白名单校验。
- 优惠价格、折扣、功效、时限等事实来自活动数据，不由 LLM 自由编造。缺少事实时明确报出缺项，不自动补造；人工审批流程与自动生成内容的授权范围见第十节待确认项。
- 素材路径只允许 manifest 中的 ID 或 MPT/资源目录白名单路径，不能把任意路径写入 batch。
- `video_count` 大于 1 时，一个 MPT task 可产生多个视频；后处理必须遍历 `result.videos`，不能只处理一个固定文件名。

### 3.2 审核文案的固化

`--stop-at script` 只产生并返回脚本，不会自动续跑。人工审核后必须把审核后的 `video_script` 明确写入下一次 batch JSONL；否则下一次运行可能再次调用 LLM 并生成不同文案。

建议流程：

1. selector 生成带 `job_id` 的输入快照和初稿。
2. 人工审核并保存最终 `video_script`，记录修改人和时间。
3. selector 使用最终脚本生成 MPT batch JSONL。
4. batch JSONL 中只放当前 CLI 接受的 `VideoParams` 字段；未知字段直接报错。

### 3.3 自动生成与人工模板入口

- 自动入口：selector 根据分类、主题和活动事实生成素材选择与后处理配置，保存最终使用的脚本和配置快照。
- 人工入口：人工填写 batch JSONL 和逐任务后处理模板，可跳过 selector 的 LLM 分类与文案生成；仍执行相同的路径校验、任务映射和素材登记。
- 已有 MPT 成片入口：提供原片路径和后处理模板，可单独运行阶段三；仍建立 job/task/variant 记录和输入指纹，不重新调用 LLM、TTS 或 MPT。
- `custom_texts=[]` 表示不叠加指定文字，无需另设跳过开关。

### 3.4 素材清单与 BGM 接入

manifest 至少保存素材 ID、分类、真实路径、媒体类型、时长、尺寸及内容哈希；BGM 保存 ID、分类、路径和时长。selector 将 ID 解析为当前 CLI 接受的素材对象（`video_source=local`、`video_materials`），不能把 ID 直接当成文件路径提交。

BGM 先导入 MPT 的 `storage/bgm` 或 `resource/songs` 受管目录，再填 `bgm_type=custom` 和 `bgm_file`。当前实现由 `selector.py` 使用 manifest ID 将 BGM 复制到 `storage/bgm/{asset_id}{suffix}`，同内容可复用，不同内容拒绝覆盖；保留外部音乐库到导入文件的对应关系。不要假设目录内指向外部文件的软链接能绕过真实路径校验；若部署使用挂载或整个目录软链接，必须验证解析后的白名单边界。字体和 Logo 的外挂路径独立解析；不宣称 MPT 已有 Logo 管理功能。

### 3.5 素材去重状态

素材状态至少分为 `available`、`reserved`、`committed`、`released`：

- 阶段一选中后原子记录 `reserved`，避免同批或并发任务重复占用。
- 占用归属为 `job_id + task_index`。同一 task 的多个变体可共用素材池；跨 task 的去重范围（全库、活动或时间窗口）须在实施前确认，不默认永久禁用素材。
- 至少一个变体完成并通过验收后，该 task 已选择的视频素材转为 `committed`，避免部分成功后被再次分配。当前按选择集合记账，不能宣称精确识别了成片实际出现的全部源片段。
- MPT 或后处理失败但仍保留重跑资格时，继续 `reserved`；已有成功变体则保持 `committed`，不因其他变体失败而回退。
- 仅在明确放弃任务、确认没有成功产物后转为 `released`。已释放任务不能直接恢复旧输出流程，需重新检查并取得占用；冲突显式报错。进程异常中断保留占用与错误上下文，由恢复流程核对，不按超时静默释放。
- 状态更新必须保留 `job_id` 和时间；失败写入原因，不覆盖历史记录。

建议先验证顺序执行，不将其作为已批准的硬限制。若允许多进程，预占检查与写入必须在同一原子操作中完成；最终并发方案取决于目标产量。BGM 是否参与防重复单独确认，不默认与视频实行同一规则。

## 四、后处理配置契约

每个 `job_id + task_index` 生成 `post_process_specs/{task_index}.json`。以下 JSON 是单任务配置，不是整批共享配置。未知字段、非法枚举、负时间、不可访问资源均显式报错；实际视频时长、图层边界在阶段三读取每个原片后校验，不能声称阶段一已完成全部校验。缺省值在规范化时显式写入；非法值不得回退到默认值。

```json
{
  "schema_version": 1,
  "task_index": 1,
  "output": {
    "profile_id": "portrait-test-v1",
    "width": 1080,
    "height": 1920,
    "fps": 30,
    "fit_mode": "contain",
    "background_color": "#000000",
    "video_codec": "libx264",
    "pixel_format": "yuv420p",
    "video_bitrate": "1800k",
    "audio_required": true,
    "audio_codec": "aac",
    "audio_bitrate": "128k",
    "faststart": true
  },
  "watermark": {
    "enabled": true,
    "logo_path": "watermark/logo.png",
    "trim_transparent": true,
    "position": "top_right",
    "custom_xy_ratio": null,
    "margin_px": 20,
    "opacity": 0.85,
    "height_ratio": 0.08
  },
  "custom_texts": [
    {
      "text": "限时5折",
      "start": 0.0,
      "end": 3.0,
      "font_name": "STHeitiMedium.ttc",
      "font_size_px": 90,
      "color": "#FF3B30",
      "stroke_color": "#FFFFFF",
      "stroke_width_px": 2,
      "x_ratio": 0.5,
      "y_ratio": 0.15,
      "animation": "letter_by_letter",
      "stagger": 0.08,
      "pop_duration": 0.18
    }
  ]
}
```

### 4.1 字段规则

| 字段 | 规则 |
|---|---|
| `schema_version` | 当前为 `1`；不支持的版本直接拒绝 |
| `watermark.position` | `top_left`、`top_right`、`bottom_left`、`bottom_right`、`custom` |
| `custom_xy_ratio` | 仅 `custom` 使用；`[x, y]` 均为 0–1，坐标表示 Logo 中心 |
| `trim_transparent` | 去除 Logo 完全透明外框；不裁切任何可见像素，空 Logo 直接报错 |
| `margin_px` | 角落位置的目标画布像素边距 |
| `opacity` | 0–1（含端点），不引入未定义的最低透明度阈值 |
| `height_ratio` | 目标画布高度比例，必须大于 0 且使 Logo 完整落在安全区域内 |
| `custom_texts` | 可为空；每条文字必须满足 `0 <= start < end <= video.duration` |
| `output.profile_id` | 内置 `portrait-1080x1920`、`landscape-1920x1080`、`square-1080`、`portrait-test-v1`，或由 selector 的 `--profiles` 加载的完整自定义 profile |
| `font_name` | 解析到 MPT `resource/fonts` 或明确指定的字体目录，扩展名为 `.ttf/.ttc/.otf`；以真实路径校验，不因路径为绝对形式就拒绝 |
| `x_ratio/y_ratio` | 统一表示文字图层中心点，均为 0–1；不同动画不能改变锚点语义 |
| `animation` | `none`、`pop_spring`、`letter_by_letter`、`flicker_scale` |
| `letter_by_letter` | 逐字排版规则见第五节；当前支持组合标记、变体选择符、emoji modifier、ZWJ、旗帜和 keycap 集群；多行仍待确认，不能无提示丢字 |

`logo_path` 的相对路径以外挂项目根为基准；`enabled=false` 时无需 Logo。位置统一采用中心锚点，是相对 v2 自定义坐标语义的显式变更，已有模板需确认或转换，不能直接按新语义静默套用。

动画参数按所选模式填写：`none` 无动画参数；`pop_spring` 使用 `pop_duration`；`letter_by_letter` 使用 `stagger` 和 `pop_duration`；`flicker_scale` 使用 `flicker_duration`、`flicker_hz`、`scale_from`（模板值分别为 0.4 秒、8 Hz、0.6）。持续时间和频率必须为正、`stagger>=0`、`0<scale_from<=1`，所有数值须有限。字体大小为正，描边与边距非负；不额外引入未经确认的文本长度上限。

`output` 是实际生效的规格快照，不能只保存可能变化的 profile 名称。`fit_mode=contain` 等比补边，`cover` 等比居中裁切，`reject` 在宽高比不符时报错；由配置显式选择。`audio_required=true` 时缺音轨失败，为 false 时允许无声但不制造静音轨。正式版位的时长和文件大小上下限等要求在确认后写入规格及校验，示例数值不是平台标准。

生成配置后必须保存规范化 JSON 和哈希，阶段三只读取规范化版本。

## 五、阶段三：后处理实现约束

### 5.1 MoviePy 版本契约

仓库固定 `moviepy==2.2.1`，后处理脚本必须使用 v2 API：

| 不使用 | 使用 |
|---|---|
| `set_duration` | `with_duration` |
| `resize` | `resized` |
| `set_position` | `with_position` |
| 旧版隐式字体路径 | `TextClip(font=<已校验的字体文件路径>, ...)` |

视频、音频和中间 clip 必须显式关闭；读取视频使用上下文管理或等价的 `close()`，避免批量任务耗尽文件句柄。

### 5.2 水印定位

- 四角位置根据目标画布、Logo 宽高和 `margin_px` 计算。
- `custom` 使用中心锚点；所有计算结果都必须完整落在目标画布内，越界直接失败，不静默裁切或夹紧。
- Logo 先按 `height_ratio` 缩放，再计算位置；透明度在合成层设置。
- 目标规格确定后再定位，不能先按原始画面定位、再把画面强制拉伸。

设目标画布为 `W×H`、缩放后 Logo 为 `Lw×Lh`、边距为 `m`，左上角坐标分别为：左上 `(m,m)`、右上 `(W-Lw-m,m)`、左下 `(m,H-Lh-m)`、右下 `(W-Lw-m,H-Lh-m)`；custom 为 `(W*rx-Lw/2,H*ry-Lh/2)`。使用 v2 的 `with_duration`、`resized`、`with_opacity`、`with_position` 构造图层，不恢复旧版接口示例。

### 5.3 指定文字的时间轴

MoviePy 的 `transform` 回调接收 clip 的局部时间。动画进度必须使用局部时间 `t_local`；`with_start(start)` 只负责把 clip 放到整片时间轴，不能在 transform 中再次减去 `start`。

每条文字统一采用以下语义：

```text
clip.with_start(start).with_duration(end - start)
动画进度 = clip 局部时间 / 动画持续时间
```

`pop_spring`、`flicker_scale` 和逐字动画都必须在 `start` 非零时通过同一测试；动画结束后应连续收敛到正常尺寸和原始字形透明度。时间区间采用 `[start,end)`。

### 5.4 颜色帧与 mask

MoviePy 的文字颜色帧和透明 mask 分开合成。闪烁变大必须让颜色帧与 mask 使用相同的缩放和画布偏移，再将 mask 乘以透明度系数。动画结束时系数回到 1，恢复原始字形 mask，保留背景透明和抗锯齿边缘；绝不能将整张 mask 填为 1。

以下是实现必须遵守的算法定义；当前基础实现已覆盖其纯计算和颜色帧/mask 变换，但仍需真实素材验收：

| 动画 | 计算与结束规则 |
|---|---|
| 无动画 | 原始文字帧及字形 mask，按配置时间显示 |
| 弹簧缩放 | 可用 `q(p)=1-exp(-6p)*cos(2.5πp)`，在 `0<=p<=1` 取 `s(p)=scale_min+(1-scale_min)*q(p)/q(1)`；模板 `scale_min=0.05`，结束后 `s=1`，明确端点连续；弹性超调需预留画布，不能裁掉描边 |
| 闪烁变大 | `p=t_local/d`，区间内 `s=scale_from+(1-scale_from)*p`；透明度乘数 `a=1-A*(1-p)*abs(sin(2π*f*t_local+π/2))`，模板振幅 `A=0.6`，首帧为 `1-A`；区间结束后 `s=a=1` |
| 逐字变大 | 每个字素独立使用弹簧缩放，局部时间从该字素出场起算，整体布局保持稳定 |

公式中的常量在实现中命名并记录；不为每个内部常量额外增加用户配置。当前 `scripts/post_process.py` 已实现这些纯计算和颜色帧/mask 同步变换，`_visual_characters` 处理组合标记、变体选择符、emoji modifier、ZWJ、旗帜和 keycap 集群，并有单元测试和实际 MoviePy 渲染测试；仍需用真实素材做观感验收。可参考现有字幕缩放的颜色帧/mask 同步方式，但外挂不直接导入 MPT 私有函数，避免绑定内部实现。端点连续不等于已经达到观感要求，仍需实片检查。

逐字动画要求：

- 使用字体的排版推进量、字距及基线安排字符，不能只累加 `getbbox` 的墨迹宽度；先得到整句布局框，再以整句中心定位，各字素使用各自偏移，不能全部堆在同一个中心。
- 设字素数为 `N`，最后出场为 `last_start=start+(N-1)*stagger`；要求 `last_start<end` 且 `last_start+pop_duration<=end`，保证末字有可见区间并能完成动画。结束后的停留时长为两者之差，是否要求最小停留时间由产品确认，不添加隐含下限。
- 字符图层和 mask 使用相同的缩放变换，避免黑色轮廓或透明边框。
- 不能将 Unicode 码点数量直接当作视觉字符数；当前已按 grapheme-like 集群分组组合字符和 emoji 序列，再用字体的 `getlength` 排版。多行仍单独处理，字体必须实际包含目标字形；缺字必须显式报告，不能静默丢弃或替换。
- 空字符串不生成图层；空数组是正常的不叠加配置。整体动画持续时间同样不能长于该条文字显示区间。

### 5.5 资源合成与导出

建议结构：

```text
VideoFileClip(raw) + watermark + custom_texts
        │
        └── CompositeVideoClip
                │
                └── 按目标规格一次性写出 final/{job_id}/...
```

默认不要先用 MoviePy 编码一次、再用 ffmpeg 有损编码一次。后处理直接按目标分辨率、帧率、视频编码、音频编码和码率写出；只有在明确需要平台专用转码时才增加一个独立转码步骤，并记录转码参数。

1080×1920、30 fps、H.264/AAC 可作为本地竖屏测试预设；它不是腾讯广告所有版位的合规承诺。比例不一致时必须明确选择裁切、补边或拒绝，不能使用无提示的强制拉伸。

## 六、阶段二与阶段三的运行契约

### 6.1 MPT 结果收集

阶段二使用 MPT 对应 Python 环境执行 `cli.py --batch-file <batch绝对路径> --stop-at video`，保存退出码、stdout 结果和 stderr。`scripts/run_pipeline.py` 通过参数数组调用，不拼接 shell 字符串。当前 MPT 输出位于自身任务目录；外挂按 `result.videos` 逐项复制到 `mpt_raw/{job_id}/{task_index}/{variant}.mp4`，校验内容哈希后登记，不移动或覆盖 MPT 原件。示意映射如下：

```json
{
  "job_id": "...",
  "task_index": 1,
  "mpt_task_id": "...",
  "status": "succeeded",
  "raw_videos": [
    {
      "variant": 1,
      "source_path": "<MPT任务目录>/final-1.mp4",
      "raw_path": "output/mpt_raw/<job_id>/1/1.mp4",
      "sha256": "<实际文件哈希>"
    }
  ],
  "error": null
}
```

`status=failed` 或缺少 `result.videos` 时，阶段三不得继续处理该条目；错误必须包含失败阶段和 MPT task ID。

当前 CLI 任一条目失败就返回非零退出码，同时仍可能输出其他成功条目。编排必须先读取退出码和结果 JSON，再逐项处理成功条目，不能用遇错退出或 `check=True` 直接丢弃结果。整批最终保留非零状态，并提供逐条报告。JSON 缺失、解析失败、条目数量/索引不符或 videos 为空均显式失败；不能猜测任务目录并声称成功。

CLI 当前在批次结束汇总结果。若中途进程退出、没有完整映射，不能声称可以无损自动续跑阶段二；保留原始日志与状态，明确报告需核对的条目。不重排同一 job 的 batch 来重试子集，以免索引错配。

### 6.2 后处理幂等与重跑

- `render_key` 由原片 SHA-256、规范化任务配置（含完整 output）、实际字体与 Logo 文件哈希、后处理实现版本及 MoviePy/FFmpeg 版本共同生成。只对启用的资源计入指纹，输入身份不得只靠文件名或修改时间。
- 只有指纹相同、状态已成功、输出存在且其内容哈希与验收记录一致时才复用；修改文案、Logo、字体、原片或导出规格均生成新目录，保留旧产物，不返回过期成片。
- 只重跑后处理时复用 `mpt_raw`，不重新调用 LLM 或 MPT。
- 写文件使用临时路径，完成 ffprobe 校验后再原子改名为最终路径。
- 任一输出失败只标记该 variant 失败；不能把同一批次的其他成功结果覆盖为失败。
- 已存在但与记录不符的产物显式报错，不自动覆盖；配置变更创建新的渲染结果，不篡改旧结果的配置快照。

## 七、校验、可观测性与回滚

### 7.1 输入校验

- 配置 JSON：schema、字段、枚举、数值范围、时间区间、字体路径、文本长度。
- MPT batch：严格遵循当前 `VideoParams` 字段，未知字段让 CLI 显式失败。
- 文件边界：MPT 输入遵循 CLI 现有规则；外挂 Logo、字体和输出目录使用显式资源根与真实路径校验，不能假设它们自动继承 MPT 校验。
- 输出规格：分辨率、帧率、编码器、码率、音频存在性、时长和文件可读性。

### 7.2 日志与状态

每阶段记录 `job_id`、`task_index`、`mpt_task_id`、输入/输出路径、配置哈希、开始/结束时间、耗时、失败阶段和异常信息。日志中不写入 API key、签名 URL 或完整外部凭据。

### 7.3 回滚边界

- 重跑资格有效期间保留外挂原片副本、配置快照及资源身份；原 MPT 文件即使被其自身清理，也不影响副本重跑。长期保留期限和磁盘预算由用户确认，不承诺永久保存，也不默认自动删除。
- 最终文件验收前只写临时文件，失败不会覆盖历史成功产物。
- 所有阶段失败均按第三节处理占用：可重跑时保留，明确放弃且无成功产物才释放；不得另外实现“遇错即释放”的分支。
- 不删除任务目录和原始素材作为“清理”手段；清理由独立的、可审计的保留策略处理。

## 八、验收标准

### 8.1 功能验收

- 四个角和 custom 中心位置的 Logo 在目标画布内，透明度和尺寸符合配置。
- 指定文字可独立于旁白出现；旁白字幕不被修改。
- `none`、`pop_spring`、`flicker_scale`、`letter_by_letter` 四种模式均支持非零 `start`。
- 多条文字时间区间互不影响；空数组等价于不添加指定文字。
- `video_count > 1` 时每个原始输出都有对应最终输出或明确失败记录。
- 同一 job 内两条 task 使用不同文字、Logo 和 output 配置，确认不会串用；人工模板与自动入口采用同一套校验，已有原片可只运行阶段三。

### 8.2 回归与质量验收

- 用 5 秒、10 秒、15 秒合成片测试开始/结束边界。
- 用中英文、数字、标点混排测试字宽、基线和中心对齐。
- 检查动画首帧无黑色轮廓，结束帧无透明度跳变。
- 检查旁白、BGM、视频时长和音画同步；使用 ffprobe 读取实际参数。
- 人工检查至少一组真实素材和一组纯色/合成测试素材。
- 检查动画终态背景仍透明、抗锯齿未丢失，最大弹性缩放不裁边；末字恰在 end 出场、动画超出 end 的配置应失败。
- 同时使用输出参数检查与实际解码检查，ffprobe 元数据本身不能证明每帧可解码、动画正确或音画同步。
- 在目标机器记录分辨率、片长、文字数/同时活跃图层数、耗时、峰值内存及磁盘增量，形成吞吐基线；没有基准前不承诺批量产能。

### 8.3 失败验收

- 非法配置、非法字体、越界位置、超时区间、未知 batch 字段必须返回非零错误。
- MPT 单条失败不应掩盖其他条目的状态。
- 后处理失败后可以只重跑阶段三，并得到相同配置哈希和可追踪结果。
- 一条 batch 失败、另一条成功时，成功条目仍后处理，整批返回失败明细；结果缺失和索引错配不进行猜测恢复。
- 后处理失败期间其他 task 不能取得其占用；部分变体成功后再失败不能释放已提交素材；放弃并释放后恢复须重新取得占用。
- 相同输入可复用；修改文案、Logo、字体或输出参数时不能复用旧成片；输出内容被修改时校验失败。

### 8.5 首次运行命令

```bash

  --output-root output \
  --resource-root .

# 4. 在同一真实 batch 上记录耗时、吞吐、字节和峰值 RSS
python -m scripts.performance \
  --job-id <job_id> \

  --mpt-root . \
  --output-root output \
  --resource-root .
```

## 十、默认值与待确认项

以下是模板和测试默认值，不代表品牌方已批准，也不替代待确认的产品决策：

- 默认不启用水印；启用后默认右上角，`margin_px=20`、`opacity=0.85`、`height_ratio=0.08`；实际品牌安全区可再调。这样未提供 Logo 时不会产生隐式失败。
- `custom_texts=[]`，指定文字为可选层；只在配置中出现时叠加。
- 同时保留人工填写和规则/LLM 生成两种入口；是否逐条人工审批、哪些事实可直接从已确认活动数据生成，需明确授权，不能默认为只能人工填写。
- 默认品牌色先使用配置中的显式颜色，不在代码中硬编码品牌色。
- 以 1080×1920 竖屏预设作为自动化测试基线；正式发布前为每个版位建立独立规格配置。

上线前必须确认：

- 腾讯广告实际版位的分辨率、时长、码率、文件大小和音频限制。
- Logo 是否需要安全区、最小尺寸或不同版位不同位置。
- 指定文字的审批人、素材/活动数据来源和敏感词规则。
- 是否允许多行文字、emoji、复杂合字；若允许，需扩大排版和测试范围。
- 目标日批量、并发规模、素材去重范围与 BGM 复用规则，以及动画结束后的最小停留时间。
- 原片、字体/Logo 快照和最终产物的保留期限、磁盘预算与清理授权。
- AI 生成的视频、配音、图片或音乐是否存在；如存在，发布前按适用法规和平台要求完成声明与显式/隐式标识，不能仅凭“视频素材是实拍”判断全片无需标识。

## 十一、本地素材语义匹配与成片时间轴（v7，实施中）

### 11.1 目标与已确认交互

目标不是仅显示素材候选，而是使最终成片中的画面、源片段和旁白语义一致。

- 保留当前流程：输入或生成文案，选择“本地文件”时才触发自动匹配并展示分镜；用户可替换或上传，再点击现有生成按钮，不新增独立审批步骤。
- 人声继续沿用现有 TTS、音色选择、上传音频和无配音模式，不自动选择人声。
- 视频库和音乐库分别配置一个根目录，递归读取子目录作为初始分类；本机通过 `webui.sh` 运行。
- 按约一万条素材设计并实测，不把该规模设为拒绝更多素材的硬上限。
- 沿用现有片段时长作为拆镜目标，通常约 3–5 秒，优先保持语义完整；每镜目标展示一个首选和两个备选，不为凑数量放入不合格素材。
- BGM 使用独立的“智能匹配本地音乐”模式；不覆盖用户选择的无音乐、随机、预设、自定义及 AI 音乐模式。
- 上传默认仅用于当前任务；明确勾选后才加入素材库。不得修改、移动或删除外部原始素材。

### 11.2 当前实现事实与缺口

当前已有 `asset_library.py` 的 SQLite 扫描、代表帧分析、模型版本记录，以及 `asset_matching.py` 的文本排序和 WebUI 候选预览。这不等于已实现完整语义分镜。

| 位置 | 当前行为 | 对效果的影响 |
|---|---|---|
| 文案拆分 | 已改为保留标点边界并以分镜原文偏移记录；不再按固定字符数硬切 | 无自然边界的超长句仍缺少模型语义拆镜 |
| 素材分析 | 整条视频约 10%、50%、90% 位置取代表帧 | 不能定位长视频中的具体动作和场景 |
| 匹配排序 | 已固定使用描述/标签重排，目录仅作低权重辅助，文件名不参与语义分数 | 仍不理解未接入向量/专用模型的同义表达 |
| 候选返回 | 已按最低相关性过滤，最多前三；没有合格素材时保留分镜缺口 | 相关性阈值仍需固定评测集校准 |
| 去重 | 已优先排除已选首选资产，候选不足不回填被排除素材 | 人工主动重复选择仍允许，符合“尽量不重复”而非硬禁用 |
| 合成输入 | 本地分镜计划已传递每镜源/目标时间，按任务快照裁切；非本地仍保留旧列表流程 | 镜头变化检测和逐片段描述仍未接入 |
| 使用记录 | 已改为最终成片成功后登记，视频和 BGM 均使用资产 ID | 数据库不可写会使任务显式进入 asset_usage 失败 |

前述问题属于当前交付缺口；第八节的历史测试通过记录不证明这些要求已满足。

### 11.3 目标链路

```text
最终文案 -> 语义分镜与画面需求
                         |
素材库 -> 镜头/片段索引 -> 语义召回 -> 约束过滤 -> 语义重排
                                                  |
                                      分镜预览、原因、替换/上传
                                                  |
点击生成 -> 原有人声流程 -> 真实旁白时间轴 -> 冻结分镜计划
                                                  |
                            指定源片段裁切 -> 合成 -> 原有后处理
```

#### 语义拆镜

文本模型读取完整文案，输出原文范围、画面需求、必须匹配项、不应出现项和表达方式（直接展示或氛围辅助）。例如“下班回家，终于可以放松一下”对应居家休息，不应仅因“工作”相关词而选办公会议。

模型不得改写旁白或补造营销事实。以原文偏移标识每个分镜，校验顺序、覆盖和无遗漏；返回未知字段、越界范围或缺失正文时明确失败。3–5 秒是目标而非强制字符切割规则。

#### 可用片段索引

先识别镜头变化，再分析片段代表帧；长而连续的镜头也需按可用时间窗口描述。索引保存源文件 ID、内容哈希、片段 ID、源起止时间、描述、人物/动作/场景/情绪标签、技术参数和分析版本。无需物理切开原视频。

例：同一视频的 0–6 秒是进门、6–12 秒是坐沙发、12–18 秒是产品特写。“放松”应选第二段，而不是从整条视频开头播放。帧摘要只是抽样证据，不能宣称完整理解所有未采样动作。

#### 召回与重排

1. 用支持中英文的语义向量表示分镜画面需求和片段描述，召回一批候选；素材向量只在内容或分析版本变化后更新。
2. 根据显式产品/品牌约束、画幅适配、有效时长和媒体质量过滤。目录分类通常作辅助，只有明确业务要求才作为硬约束；数字文件名不参与语义加权。
3. 使用文本模型或专用重排模型判断候选与画面需求是否符合，返回片段 ID、相关性判断及理由。实现时固定一个明确的重排路径，不静默切换模型。
4. 先确认内容合格，再应用近期使用软降权；不得让新鲜但无关的素材胜过相关素材。
5. 不足三个就显示真实数量；没有合格素材就显示缺口，允许人工替换或上传，不自动塞入无关画面。

召回数量和合格阈值通过固定评测集校准，不把模型自报分数当作可靠概率。约一万条规模先保留 SQLite 管理元数据，向量检索是否需要独立索引由实测决定，不默认引入独立向量数据库服务。

技术依据：[Sentence Transformers 的 Retrieve & Re-Rank 说明](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)。该依据支持两阶段检索结构，不保证本项目的实际命中率。

### 11.4 成片必须执行已选分镜

选择本地文件时先展示预计时长；正式生成后沿用当前人声流程获取真实音频。优先使用已有配音时间戳，缺少时间戳或上传音频时做文本与音频对齐，不改变人声语速。

每个分镜的任务快照至少包含：原文范围、画面需求、候选和选择理由、选中素材及哈希、源起止时间、成片起止时间、人工替换记录和分析/匹配版本。

- 以“旁白时间段 → 已选源片段 → 成片时间段”执行裁切，不能退回只有文件列表的随机拼接。
- 时长不足、文本与音频不一致或对齐失败必须明确报告，不自动改写旁白、循环其他镜头或偷偷替换素材。
- 用户选择在提交时固定；运行期间不重新排序候选。多输出视频也不得因旧随机规则打乱已选分镜。
- 同一成片尽量不重复，跨任务允许复用；不沿用外挂永久 `committed` 禁用规则。
- 内容哈希只能检测外部文件变化，不能冻结文件字节。要保证运行中外部修改不影响任务，需使用任务级内容快照或平台可验证的快照机制；保留原文件不变，并显示磁盘开销。仅保存路径时不得宣称具备该保证。
- 实际使用历史以成功成片的执行片段登记，并区分提交记录和成片使用记录。

### 11.5 BGM 与素材数据维护

BGM 根据整篇文案的情绪、节奏和风格匹配，不逐镜换歌。目录、人工标签以及“是否含人声、是否适合旁白”作为音乐库数据；未分析过的属性不得伪造。暂不默认发送音乐到云端，既有外发授权仅涵盖视频压缩代表帧。

| 数据 | 来源 | 保存与维护要求 |
|---|---|---|
| 分类、相对路径 | 目录扫描 | SQLite；保留根目录边界 |
| 片段描述、标签 | 代表帧分析 | 记录源时间段、模型和提示词版本 |
| 人工修订 | 用户修改 | 独立保存，自动重分析不得覆盖 |
| 向量 | 片段描述编码 | 记录模型版本和维度，可重建 |
| 分镜计划 | 文案分析、匹配、人工选择 | 任务级持久快照，可追溯 |
| 使用历史 | 成片执行结果 | 持久保存，不视为普通缓存 |

现有数据库为 `storage/asset_library.sqlite3`。表结构迁移需保留已有数据；缩略图和向量可以重建，但人工标签和使用历史不能作为缓存直接删除。提供标签查看/编辑、失败详情、待分析数量和显式重试入口。

### 11.6 安全、性能、可观测性与回滚

| 方面 | 风险与措施 |
|---|---|
| 安全 | 模型仅返回受控 ID；本地校验真实路径、片段范围和哈希，拒绝越界软链接；素材描述视为数据而非执行指令 |
| 外发与成本 | 索引前显示分析服务、待处理文件/片段、代表帧及预计调用量；重排优先只发文案和已有描述，扩大图片或音乐外发范围前明确授权 |
| 一致性 | 文案变更使关联计划失效；人工选择不能在提交时被静默覆盖；提交和执行快照保持关联 |
| 性能 | 增量探测、缓存分析与向量；避免每次编辑文案都重新解码全库；一万条素材下测量耗时、峰值内存和调用次数 |
| 可观测性 | 记录召回、过滤、重排、缺素材、对齐和渲染各阶段状态及原因；不记录密钥或帧 Base64 |
| 回滚 | 新语义路径独立于原上传流程；显式选择原流程，不在新路径失败后静默降级；数据库升级前备份，保留任务计划版本 |

### 11.7 实施顺序与验收

以下是实施检查点，不是可省略后续阶段的缩减交付。

| 顺序 | 工作 | 验证 |
|---|---|---|
| 1 | 无关候选拒绝、去重、分镜顺序与提交一致性 | 先建立失败回归，验证不硬凑、不误用旧选择 |
| 2 | 语义拆镜、片段索引、召回和重排 | 固定真实文案集比较旧版/新版首选命中率及前三可用率 |
| 3 | 实际旁白对齐、源片段裁切、计划执行 | 核对原文、音频、源时间和成片时间；验证多输出不乱序 |
| 4 | 标签维护、BGM 匹配、状态追溯 | 人工修订保留、失败可解释、原模式回归 |

评测使用素材库中的代表性文案，涵盖长句、同义表达、中英文、抽象情绪、指定品牌、素材不足和上传音频。由人工标注可接受候选，记录首选合适率、前三可用率、人工替换率、缺素材误判以及时间对齐误差；实施前记录旧版基线，再用同一数据集比较。具体效果门槛根据标注基线确认，不能凭主观体验或单测通过声称效果提升。

必须验证：文案原文覆盖完整；无关素材不强行返回；候选和实际成片源片段一致；人声和非本地来源行为不变；外部文件变化可检测；人工标签不丢失；一万条规模下不重复分析未变化媒体。遵守现有覆盖率门槛、60 秒后端单测调用时限和分组回归要求，未执行的云端实测、真实成片和性能检查均标记未验证。

本节的未完成项见 11.8；旧阶段的 5–10 人日估算不涵盖本节工作。
