# 本地素材库一键出片使用说明

## 这套流程解决什么问题

给定一段文案和一个本地素材目录，系统自动把文案拆成分镜、为每个分镜从素材库里挑出画面合适的**视频片段**（不是整条视频），再按旁白时间轴裁切拼接成片。目标是「一句话 + 素材 → 一键出片」。

与 MPT 原有的在线素材搜索流程相比，这套流程的素材来自你自己的库，匹配依据是视觉模型逐镜头生成的画面描述。

## 前置准备

### 1. 准备素材目录

素材按子目录分类存放，子目录名会成为素材的初始分类，参与匹配打分（低权重）：

```text
resource/videos/
├── 玉米/
│   ├── 1.mp4
│   └── 2.mp4
└── 美妆/
    └── 1.mp4
```

分类名用中文即可。支持的视频格式与 MPT 上传素材一致。

### 2. 配置目录

`config.toml` 中：

```toml
local_video_library_directory = "/绝对路径/resource/videos"
local_bgm_library_directory = ""   # 可选，背景音乐库
```

也可以在 WebUI 的「设置 → 素材来源设置 → 本地素材库」里填写。

### 3. 配置视觉模型

索引阶段要对每个镜头窗口调用视觉模型生成画面描述，因此必须配置一个**支持图片输入**的模型（`llm_provider` 及对应的 `*_model_name`）。纯文本模型无法完成索引。

## 建立索引

WebUI「设置 → 素材来源设置 → 本地素材库 → 更新本地素材索引」。

索引过程对每条素材：

1. 用 ffmpeg 检测镜头切换（`scene > 0.3`），再叠加 3–5 秒窗口规则，得到若干**源时间窗口**；
2. 每个窗口取中点抽一帧，一次视觉调用最多带 6 帧，逐窗口生成描述和标签；
3. 窗口描述汇总成资产级描述，逐窗口结果写入 `segments` 表。

索引是增量的：文件内容哈希未变且分析版本未变的素材会跳过，不重复消耗模型调用。

**成本预估**：视觉调用次数 ≈ 每条素材的窗口数 ÷ 6 向上取整。9 条真实素材（共 55 窗）约 10 次调用。

### 什么时候必须重新索引

- 新增、删除素材文件
- **重命名或替换素材文件**——资产 ID 含内容哈希与相对路径，改名后旧索引会指向不存在的文件，生成时报 `asset path is unavailable or outside its root`
- 升级后分析版本号变化（当前 `mpt-local-vision-v2`）

索引数据库在 `storage/asset_library.sqlite3`，删除即可全量重建。

## 出片流程

1. 「视频来源」选择**本地素材**；
2. 填写或生成文案；
3. 页面出现「已自动选好 N 个分镜」折叠区，展开可看到每镜的候选与选择结果；
4. 点生成。

### 分镜是怎么拆的

优先调用文本模型按语义拆镜，模型会为每镜给出：画面需求（`visual_query`）、必须出现的元素、不应出现的元素，以及该镜是 `direct`（画面直接展示这句话的内容）还是 `ambience`（抽象或情绪句，画面只需氛围相符）。

模型不可用或返回不合法时，退回按标点拆分，不影响出片。

拆镜必须逐字覆盖原文，模型不得改写、翻译或漏掉旁白。

### 候选是怎么排的

对每个分镜，按片段描述与标签同查询词的 token 交集打分（交集数除以两边 token 数的几何平均），再叠加：

- 目录分类命中的低权重加分
- 「必须出现的元素」命中的加分（**加分不是硬过滤**——模型想象的画面元素多半不会逐字出现在素材描述里，硬过滤会把整库滤空）
- 近期使用过的素材扣分（避免同一条素材反复出现）

「不应出现的元素」是**硬过滤**：命中即排除，宁可留缺口也不把明确不该出现的画面塞进来。

每镜最多 3 个候选，同一条视频不会在一镜里占多个候选位；首选素材会被后续分镜排除，避免整片重复用同一条视频。

主题/关键词默认拼接到每镜的查询词里，但模型判为 `direct` 的镜不拼——直述镜自己已经说清要什么画面，再拼上下文会把「现在下单立减」这类短句的语义冲掉。

## 缺口镜：没有相关素材时怎么办

匹配器**不会**为了凑满而返回无关素材。当一镜找不到相关片段时，该镜显示为缺口，并给出「为该镜人工选择素材」的下拉框，列出库里全部已索引素材。

缺口镜默认**不预选**任何素材——匹配器故意不硬凑，界面也不替你决定。你有三个选择：

1. 从下拉框里人工挑一条素材（整条可用，裁切范围为素材全长，不参与相关性打分）；
2. 改文案，让这一镜有可用画面；
3. 往素材库补充素材并重新索引。

三者都不做就点生成，会报错并指明是哪一镜缺素材：

```text
本地分镜匹配失败: storyboard selections do not cover all shots: shot 2 has no selected material
```

## 人工修正素材标注

自动生成的描述有时与画面不符。「设置 → 素材来源设置 → 素材标注」可以人工修正：

- **人工描述**：匹配时代替自动描述使用。留空则继续用自动描述。
- **人工标签**：追加在自动标签之后，不替换自动标签。用逗号分隔。

界面会同时显示被覆盖的自动描述与自动标签，便于对照。人工标注单独存储，**重新索引不会覆盖**，清空即恢复自动结果。保存后会重新匹配分镜。

## 成片时间轴

候选确认后冻结为分镜计划，记录每镜的源文件、内容哈希、源起止时间和目标起止时间。执行阶段：

- 按真实旁白/字幕时间轴校验并对齐目标时间；
- 按源起止时间裁切素材片段，按目标时间顺序拼接；
- 建立任务级源文件快照，外部文件在执行期间发生变化时**显式失败**，不静默使用旧内容。

启用本地分镜后拼接顺序锁定为顺序拼接——文案顺序匹配全程保持叙事顺序，随机拼接与实际执行逻辑矛盾。

素材的使用次数只在成片**成功后**登记，提交阶段不提前计数。

## 评测与规模基线

### 匹配效果评测

```bash
.venv/bin/python -m scripts.matching_eval \
  --eval-set test/resources/matching_eval_set.json \
  --baseline test/resources/matching_eval_baseline.json
```

评测集是人工标注的：每条期望给出可接受素材、禁选素材，或明确要求留缺口。指标包括首选命中率、前三可用率、禁选命中率、缺素材误判率。有指标劣于基线时脚本返回 1。

`--write-baseline <路径>` 把本次结果记为新基线。

**注意**：标注引用的资产 ID 含内容哈希，素材被替换或重新编码后 ID 会变，脚本会显式报 `eval set references assets missing from the index` 并要求重新标注——而不是让命中率静默掉到 0。

### 规模基线

```bash
.venv/bin/python -m scripts.matching_scale \
  --library-root /tmp/mpt_scale_10k/videos \
  --db-path /tmp/mpt_scale_10k/index.sqlite3 \
  --asset-count 10000 --keep-media
```

用合成素材测一万条规模下的冷扫描耗时、增量重扫耗时、视觉调用量、峰值内存和查询耗时。视觉模型用确定性替身，**因此报告里的耗时不含真实模型延迟与费用**。

当前基线（`test/resources/matching_scale_baseline.json`）：一万条素材 / 三万片段，冷扫描约 66 分钟，未变化媒体重扫 1.8 秒且 0 次视觉调用，峰值内存 203 MB，单次匹配约 2 秒。

匹配耗时的构成：读全部片段约 0.8 秒、建倒排索引约 1.0 秒、打分约 0.15 秒。倒排索引每次匹配只建一次（一条文案通常 2–4 镜，逐镜重建会更慢）。

## 已知边界

- **向量召回未实现**：当前是词面匹配，同义表达匹配不上。英文 `vacuum packed` 与中文「真空包装」不会互相命中。
- **禁选/可接受标注是资产级**：逐窗口索引之后，整条视频被标为禁选会误伤该视频里本来合适的窗口。评测集下一次重标应改为片段级。
- **BGM 匹配用资产级描述**：BGM 没有片段索引，描述、标签和目录分类是唯一语义来源，且不套用零交集剪枝（零交集片段仍可能凭近期使用惩罚参与排序）。
- **真实观感未验收**：已有自动化回归和合成渲染检查；真实素材观感、品牌视觉和平台版位参数仍需人工验收。
